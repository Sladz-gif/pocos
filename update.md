# POCOS — PRODUCT BRIEF

## App Name & Identity
- **Name:** Pocos
- **Tagline:** "Every herd. Every story."
- **Platform:** iOS & Android via Expo (React Native + TypeScript)
- **Purpose:** Pocos is a dual-sided ranch management and livestock marketplace platform. On one side it gives ranch businesses a complete operational tool — livestock records, medication tracking, breeding ancestry, task management, team chat, and a storefront. On the other side it gives individual buyers a clean marketplace to browse and purchase cattle, beef, milk, and feed directly from verified ranches.

## Colour Palette & Design Language

Do NOT use generic green and white farm colours. Pocos uses a warm, editorial, earthy-luxury palette that feels closer to a premium leather goods brand than a farm app.


**Typography:**

**Overall feel:** Warm, confident, structured. Think a leather-bound ranch ledger gone digital. Heavy use of parchment-toned backgrounds, rust accent touches, and deep plum for authority/admin sections.

## Safe Area & Navigation Rules

- Wrap every screen root in `<SafeAreaView style={{ flex: 1, backgroundColor: '#FAF6EF' }}>` from `react-native-safe-area-context`. This prevents overlap with the phone's status bar at the top and home indicator bar at the bottom on all iOS and Android devices.
- Use `useSafeAreaInsets()` wherever you need dynamic padding (e.g. floating bottom bars, modals that slide up from the bottom).
- The bottom tab navigator must have `paddingBottom` set using the safe area bottom inset so it never overlaps the phone's home bar.
- Never hardcode pixel values for top/bottom safe zones — always use insets from the context.
- StatusBar style: `dark-content` on parchment screens, `light-content` on deep plum screens.

## User Roles & Authentication

### Three distinct user types that the app handles:

**1. Super Admin (Ranch Owner)**
- Created during initial ranch onboarding
- Has complete access to every feature: livestock, tasks, chat, store management, staff monitoring, admin panel
- The only person who can onboard staff, generate access codes, assign store manager role, manage the store
- Logs in with email + password (set during onboarding)

**2. Ranch Staff (Team Member)**
- Created by the Super Admin
- Logs in with a unique alphanumeric access code generated by the Super Admin (e.g. `JM-4829`)
- Has access to: livestock records, tasks, team chat
- Does NOT have access to: store, admin panel, staff monitoring
- Exception: if Super Admin assigns a staff member as Store Manager, they also get access to the Store tab and store features

**3. Store Manager (Staff sub-role)**
- A regular staff member elevated to Store Manager by the Super Admin
- Gets everything a staff member gets PLUS the Store tab (Tab 5)
- Can manage listings, approve/hide items, apply discounts
- Cannot access the Admin panel or staff monitoring

**4. Consumer (Buyer — separate app entry point)**
- Signs up independently, not created by the Admin
- Sees only the Marketplace / buyer-facing interface
- Has no access to ranch operational tools
- When they open Pocos, after selecting "I want to buy" on the welcome screen, they land in the Marketplace mode

### 2D — Breeding

This is the most data-rich section. It handles pregnancy tracking, nursing, and the full traceable family tree.

**Pregnancy Records screen:**
- Header: "Breeding Records"
- Sub-tabs: "Pregnancies" | "Nursing" | "Ancestry"

**Pregnancies tab:**
Each pregnancy record card shows:
- Dam (mother) — ID and name, tappable
- Sire (father) — ID and name, tappable. If the sire was an external animal (not in the system), show "External Sire" and the note field.
- Mating date
- Expected delivery date (auto-calculated: mating date + 283 days for cattle, but allow manual override)
- Status badge: "Pregnant" (amber) | "Delivered" (green) | "Lost" (crimson)
- If delivered: shows calf IDs born from this pregnancy (each tappable → calf's profile)

**Add Pregnancy Record screen:**
- **Dam (Mother)** — searchable picker. Required. Only shows females.
- **Sire (Father)** — searchable picker. Shows males in the system. Plus a toggle "Sire is external (not in this system)". If external, show a text field "External Sire ID / Description".
- **Mating Date** — date picker. Required.
- **Expected Delivery** — auto-calculated but editable date picker.
- **Notes** — optional
- Save

**Nursing tab:**
Shows all female animals currently nursing. Each card:
- Mother animal ID and name
- Calf being nursed (ID, tappable)
- Date nursing started
- Status: "Nursing" (green) | "Weaned" (grey)
- Button: "Mark as Weaned"

**Ancestry tab (Family Tree):**
This is a visual and navigable family tree for each animal.

UI approach:
- Search / select an animal at the top
- The tree renders below showing 3 levels: Grandparents (if known) → Parents → Selected Animal → Calves born

Each node in the tree is a rounded card/pill showing: Animal ID, name, sex icon, and breed status (born/purchased). Nodes are connected with lines.

Use `react-native-svg` to render the connecting lines between nodes.

**Data traceability rules (critical for accuracy):**
- When an animal is created as "Purchased", their dam/sire fields may be empty (unknown). This is fine — the tree simply shows "Unknown Dam / Unknown Sire" as greyed-out placeholder nodes.
- When a mating event is logged (dam + sire → pregnancy), that relationship is permanently stored.
- When a calf is born (delivery logged), the calf's profile is automatically linked as a child of both dam and sire.
- When a calf is then grown up and breeds, its own calves are added below it. This creates an infinitely deep chain.
- Every animal that is bought and mated has a full forward lineage even if their own past is unknown.
- Tapping any node in the tree navigates to that animal's full detail screen.
- The tree is scrollable both vertically and horizontally if it grows wide.

**Message persistence:**

## IMPORTANT UX RULES

1. **No task is ever auto-deleted.** Every deletion requires the `PDeleteModal` confirmation.
2. **Completed tasks move to the Completed section** — they never disappear. Users own their history.
3. **Medication alerts** use both in-app banners (on Home screen) and scheduled local push notifications via `expo-notifications`.
4. **The ancestry tree must always be traceable** — even if a link in the chain is unknown, the tree renders with "Unknown" placeholder nodes. No broken trees.
5. **Role-based access is enforced at the navigator level** — Tab 5 is not rendered in the tab bar at all for regular staff. The Admin Panel gear icon on the Home screen is only rendered for the Super Admin.
6. **Store listing changes are immediate** — toggling a listing from "Listed" to "Unlisted" updates it immediately and it disappears from buyer view.
7. **When a Store Manager or Super Admin views Buyer Preview**, a persistent "Return to manage view" banner is always visible so they are never stuck.
8. **All date/time fields use Expo's `DateTimePicker`** via `@react-native-community/datetimepicker`.
9. **All scrollable lists use `FlatList`** (not ScrollView + map) for performance.
10. **KeyboardAvoidingView** must be applied on every screen with a text input, especially the chat screen.
